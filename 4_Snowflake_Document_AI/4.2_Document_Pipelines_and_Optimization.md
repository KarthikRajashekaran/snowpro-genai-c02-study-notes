# 4.2 Document Pipelines & Optimization

This section covers C02 objectives **4.2** (prepare and manage documents), **4.3** (build automated document-processing pipelines with Cortex AI), and **4.4** (troubleshoot and optimize).

---

## 4.2 — Prepare and Manage Documents

Before any parsing or extraction, documents must be **staged** in Snowflake and the stage must expose them for the Cortex document functions.

### Upload documents to a stage

```sql
-- 1. Create an internal stage with a directory table + encryption
CREATE OR REPLACE STAGE doc_stage
    DIRECTORY = (ENABLE = TRUE)
    ENCRYPTION = (TYPE = 'SNOWFLAKE_SSE');   -- server-side encryption required for Cortex file access

-- 2. Upload files (SnowSQL / Snowsight / driver)
PUT file:///local/path/invoices/*.pdf @doc_stage/invoices/ AUTO_COMPRESS = FALSE;

-- 3. Refresh the directory table so new files are visible
ALTER STAGE doc_stage REFRESH;

-- 4. List what's staged
SELECT relative_path, size, last_modified
FROM DIRECTORY(@doc_stage);
```

Key points:
- **`DIRECTORY = (ENABLE = TRUE)`** creates a directory table — required for listing files and for Stream-based pipelines.
- **Internal stages must use server-side encryption** (`SNOWFLAKE_SSE`) for Cortex to read the files; client-side encrypted stages are not supported.
- **External stages** (S3/Azure/GCS) work too, with a storage integration.
- Use `AUTO_COMPRESS = FALSE` for binary documents (PDF, images) so they aren't gzip-wrapped.

### Requirements — formats and size limits

| Requirement | Detail |
|-------------|--------|
| **Supported formats** | PDF, DOCX, PPTX, and images (JPEG, PNG, TIFF) — document and image types; not spreadsheets |
| **Stage type** | Internal (SSE-encrypted) or external stage with a directory table |
| **File size** | Bounded per-file maximum (large multi-hundred-MB files are rejected) — split very large files |
| **Page limits** | Very high page counts should be capped with `page_limit`; process in slices for huge documents |
| **Encoding** | Files must be readable/non-corrupt; password-protected PDFs fail |

> Exact size/page ceilings change over time; on the exam, the testable idea is that **limits exist**, oversized files fail, and you control page volume with `page_limit`.

### Implement an extracting workflow

A basic extracting workflow: stage → parse (optional) → extract → persist.

```sql
-- Persist structured extraction results into a table
CREATE OR REPLACE TABLE invoice_fields AS
SELECT
    relative_path                    AS file_name,
    AI_EXTRACT(
        file => TO_FILE('@doc_stage', relative_path),
        responseFormat => {
            'vendor_name'   : 'Vendor or supplier name',
            'invoice_total' : 'Total amount due, numbers only',
            'invoice_date'  : 'Invoice date in YYYY-MM-DD'
        }
    )                                AS extracted,
    CURRENT_TIMESTAMP()              AS processed_at
FROM DIRECTORY(@doc_stage)
WHERE relative_path ILIKE 'invoices/%.pdf';
```

## 4.3 — Build Automated Document Processing Pipelines with Cortex AI

Automate processing so files are handled **as they land**, using Snowflake-native orchestration: **Streams** (change detection) + **Tasks** (scheduled execution). No external orchestrator needed.

### Architecture

```
Files uploaded → Stage (directory table) → Stream (new files) → Task (runs AI_PARSE_DOCUMENT / AI_EXTRACT) → Results table → Downstream (RAG, analytics)
```

### Step 1 — Stream on the directory table

A stream on a directory-enabled stage captures **newly added files**.

```sql
CREATE OR REPLACE STREAM doc_stream
    ON STAGE doc_stage;   -- tracks changes to the directory table
```

### Step 2 — Results table

```sql
CREATE OR REPLACE TABLE parsed_documents (
    file_name     STRING,
    content       STRING,
    page_count    INT,
    processed_at  TIMESTAMP_NTZ
);
```

### Step 3 — Task that consumes the stream

```sql
CREATE OR REPLACE TASK process_documents_task
    WAREHOUSE = doc_wh
    SCHEDULE  = '5 MINUTE'
    WHEN SYSTEM$STREAM_HAS_DATA('doc_stream')   -- only runs when new files exist
AS
INSERT INTO parsed_documents
SELECT
    relative_path,
    AI_PARSE_DOCUMENT(
        TO_FILE('@doc_stage', relative_path),
        {'mode': 'LAYOUT', 'page_limit': 20}
    ):content::STRING                           AS content,
    AI_PARSE_DOCUMENT(
        TO_FILE('@doc_stage', relative_path),
        {'mode': 'LAYOUT'}
    ):metadata:pageCount::INT                   AS page_count,
    CURRENT_TIMESTAMP()
FROM doc_stream
WHERE METADATA$ACTION = 'INSERT';               -- newly added files only

-- Tasks are created SUSPENDED; resume to activate
ALTER TASK process_documents_task RESUME;
```

Key orchestration points:
- **`WHEN SYSTEM$STREAM_HAS_DATA(...)`** skips runs when there's nothing new — saves credits.
- **Consuming the stream** (reading it in a DML statement inside the task) advances its offset so files aren't reprocessed.
- Chain tasks (`AFTER`) to add an extraction step after parsing, or an embedding step for RAG.

### Optional — chained extraction task (Task DAG)

```sql
CREATE OR REPLACE TASK extract_fields_task
    WAREHOUSE = doc_wh
    AFTER process_documents_task   -- runs after parsing completes
AS
INSERT INTO invoice_fields
SELECT
    file_name,
    AI_EXTRACT(
        text => content,
        responseFormat => { 'vendor_name':'Vendor name', 'invoice_total':'Total due, numbers only' }
    ),
    CURRENT_TIMESTAMP()
FROM parsed_documents
WHERE processed_at >= DATEADD('minute', -6, CURRENT_TIMESTAMP());

ALTER TASK extract_fields_task RESUME;
```

## 4.4 — Troubleshoot and Optimize

### Extracting query errors & file access

Most document-pipeline failures are **file access** problems, not model problems. Snowflake provides two URL functions to reach staged files.

| Function | Returns | Use when |
|----------|---------|----------|
| **`GET_PRESIGNED_URL`** | A temporary, **pre-authenticated public URL** to a staged file (valid for an expiry window) | You need to fetch/inspect a file directly, share it briefly, or debug that a file is reachable |
| **`BUILD_SCOPED_FILE_URL`** | A **scoped URL** that enforces Snowflake privileges each time it's accessed | You need a permission-checked reference passed between Snowflake operations (safer default) |

```sql
-- Presigned URL: temporary public link (expires after the given seconds)
SELECT GET_PRESIGNED_URL(@doc_stage, 'invoices/inv_001.pdf', 3600) AS presigned_url;

-- Scoped file URL: permission-enforced reference
SELECT BUILD_SCOPED_FILE_URL(@doc_stage, 'invoices/inv_001.pdf') AS scoped_url;
```

**Troubleshooting checklist:**
- **File not found / null content** → run `ALTER STAGE … REFRESH`; verify `relative_path` (case-sensitive) via `DIRECTORY(@stage)`.
- **Access denied** → grant `USAGE` on the stage and `READ`; confirm the storage integration for external stages.
- **Unsupported/corrupt file** → check format and that the PDF isn't password-protected; re-upload with `AUTO_COMPRESS = FALSE`.
- **Query too slow / times out** → add `page_limit`, size up the warehouse, or process in batches.
- **Stream reprocessing files** → ensure the task actually consumes the stream (DML that reads it advances the offset).

### Requirements and privileges

- **`SNOWFLAKE.CORTEX_USER`** database role is required to call the Cortex document functions (`AI_PARSE_DOCUMENT`, `AI_EXTRACT`).
- **`USAGE`** on the stage's database/schema and the stage, plus **`READ`** on the stage, to reach files.
- **`DIRECTORY = (ENABLE = TRUE)`** on the stage for directory tables and streams.
- Cortex document functions run in **specific regions**; cross-region use may require cross-region inference to be enabled.

```sql
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER TO ROLE doc_processor_role;
GRANT USAGE ON STAGE doc_stage TO ROLE doc_processor_role;
```

### Cost and best-practice considerations

- **Use `page_limit`** — document functions are priced by pages/content processed; cap pages you don't need.
- **Process incrementally** — Streams + `SYSTEM$STREAM_HAS_DATA` ensure you only pay for new files.
- **Right-size the warehouse** — document parsing is bursty; a small/medium warehouse with auto-suspend is usually enough. Avoid oversized warehouses idling.
- **Batch small files** in a single task run rather than one task per file.
- **Parse once, reuse** — persist `AI_PARSE_DOCUMENT` output, then run multiple `AI_EXTRACT` schemas against the stored text instead of re-parsing.
- **Chunk large documents** with `page_split` for RAG rather than embedding whole documents.

### Fine-tuning arctic-extract models

When out-of-the-box extraction accuracy on a **specialized document type** (e.g., a specific invoice or claim layout) is insufficient, you can **fine-tune an arctic-extract model**:

- **arctic-extract** is Snowflake's document-extraction model family that backs `AI_EXTRACT`.
- Fine-tuning trains the model on **your labeled document/field examples** so it learns your specific layouts and terminology, improving field accuracy over the base model.
- Provide representative training documents with the correct target field values; validate on a held-out set.
- Use fine-tuning when prompt engineering alone (clear questions, constrained `responseFormat`) has plateaued and you have enough labeled examples.
- **Trade-off:** fine-tuning adds training cost and maintenance — reach for it only after prompt engineering and parse-then-extract chaining are exhausted.

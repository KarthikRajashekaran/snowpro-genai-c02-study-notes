# 2.2 AI_COMPLETE / COMPLETE — Deep Dive

`AI_COMPLETE` is the general-purpose generation function and the most important single function on the exam. It replaces the legacy `COMPLETE` (which still works as an alias). This page covers its signatures, **structured outputs (JSON schema)**, model selection, options, `TRY_COMPLETE`, and **single-file / multimodal** completion.

## Signatures

`AI_COMPLETE` has two main shapes:

```sql
-- 1) Single-string prompt
AI_COMPLETE( <model>, <prompt> [, <model_parameters> ] [, <response_format> ] [, <show_details> ] )

-- 2) Multi-message / multimodal (named args)
AI_COMPLETE(
    model            => <model>,
    prompt           => <string | PROMPT(...) | array_of_messages>,
    model_parameters => { 'temperature': .., 'max_tokens': .., 'top_p': .. },
    response_format  => { ...json schema... },
    show_details     => TRUE
);
```

```sql
-- Legacy alias — identical behavior
SELECT SNOWFLAKE.CORTEX.COMPLETE('llama3.1-70b', 'Say hello');
```

## Model selection

Choose by capability / latency / cost. Bigger = smarter & slower & pricier.

```sql
-- Large (complex reasoning, highest quality)
AI_COMPLETE('claude-3-5-sonnet', p)   -- strong all-round reasoning
AI_COMPLETE('llama3.1-405b',     p)   -- largest open model
AI_COMPLETE('mistral-large2',    p)   -- multilingual, top-tier

-- Medium (balanced)
AI_COMPLETE('llama3.1-70b',      p)
AI_COMPLETE('mixtral-8x7b',      p)
AI_COMPLETE('snowflake-arctic',  p)

-- Small (fast, cheap, high throughput)
AI_COMPLETE('llama3.1-8b',       p)
AI_COMPLETE('mistral-7b',        p)
```

**Rule of thumb:** start on the smallest model that meets quality; escalate only where accuracy demands it. Use `AI_COUNT_TOKENS` to stay within a model's context window (see [2.3](./2.3_Vector_and_Helper_Functions.md)).

## Options (model_parameters)

| Parameter | Effect | Typical value |
|-----------|--------|---------------|
| `temperature` | Randomness. 0 = deterministic/factual, higher = creative | 0.0–0.3 factual, 0.7–0.9 creative |
| `max_tokens` | Cap on generated length | task-dependent |
| `top_p` | Nucleus sampling; diversity via cumulative probability mass | 0.9 |

```sql
SELECT AI_COMPLETE(
    'llama3.1-70b',
    'Summarize the benefits of cloud computing.',
    {'temperature': 0.2, 'max_tokens': 200, 'top_p': 0.9}
);
```

## show_details

Set `show_details => TRUE` to get an object with the response **plus** metadata (model, token usage, finish reason) — useful for monitoring and cost tracking.

```sql
SELECT AI_COMPLETE(
    model => 'llama3.1-8b',
    prompt => 'One-line joke about databases',
    show_details => TRUE
) AS result;   -- result:choices, result:usage.total_tokens, ...
```

## Structured Outputs (JSON schema)

The exam-critical feature: pass `response_format` with a **JSON schema** and the model is constrained to return **schema-valid JSON**. This is what makes output reliably parseable — not prompt wording alone.

```sql
SELECT AI_COMPLETE(
    model  => 'claude-3-5-sonnet',
    prompt => 'Extract the ticket details: ' || ticket_body,
    response_format => {
        'type': 'json',
        'schema': {
            'type': 'object',
            'properties': {
                'category': {'type': 'string',
                             'enum': ['billing','technical','account','other']},
                'priority': {'type': 'string', 'enum': ['low','medium','high']},
                'summary':  {'type': 'string'},
                'is_urgent':{'type': 'boolean'}
            },
            'required': ['category','priority','summary','is_urgent']
        }
    }
) AS structured
FROM support_tickets;
```

The result is JSON you can address directly:

```sql
SELECT structured:category::string, structured:is_urgent::boolean
FROM ( ...query above... );
```

**Why it matters:** structured outputs turn an LLM into a typed extraction/classification engine feeding downstream SQL — categories are constrained by `enum`, required fields are guaranteed present, and there is no brittle string parsing. Prefer this over asking the model "reply in JSON" in the prompt.

## TRY_COMPLETE — error-safe generation

`TRY_COMPLETE` behaves like `AI_COMPLETE`/`COMPLETE` but returns **NULL instead of raising** on error (bad input, transient failure). Essential for batch pipelines where one bad row shouldn't fail the whole statement.

```sql
SELECT
    id,
    COALESCE(
        TRY_COMPLETE('llama3.1-8b', 'Summarize: ' || body),
        'processing failed — manual review'
    ) AS summary
FROM documents;
```

Progressive fallback pattern:

```sql
SELECT id,
    COALESCE(
        TRY_COMPLETE('llama3.1-405b', complex_prompt),  -- best first
        TRY_COMPLETE('llama3.1-70b',  complex_prompt),  -- cheaper fallback
        TRY_COMPLETE('llama3.1-8b',   simple_prompt),   -- last resort
        'all attempts failed'
    ) AS result
FROM tasks;
```

## Single-file & Multimodal completion

`AI_COMPLETE` can take **images** (and other files) via `TO_FILE()` and the `PROMPT()` helper — analyze a picture, read a scanned page, caption an image, all in SQL.

```sql
-- Describe / analyze a single image file from a stage
SELECT AI_COMPLETE(
    'claude-3-5-sonnet',
    PROMPT('Describe what is happening in this image: {0}',
           TO_FILE('@images_stage', 'store_shelf.jpg'))
) AS description;

-- Multimodal over a whole table of images
SELECT file_name,
       AI_COMPLETE('claude-3-5-sonnet',
           PROMPT('Is this product damaged? Answer yes/no and why. {0}',
                  TO_FILE('@images_stage', file_name))) AS assessment
FROM product_photos;
```

- `TO_FILE('@stage','path')` builds a **FILE** value that references staged content (image/audio/doc).
- `PROMPT('… {0} … {1}', a, b)` builds a prompt object, substituting positional placeholders — the mechanism for mixing text and file references in one prompt. See [2.3](./2.3_Vector_and_Helper_Functions.md).
- Use a **multimodal-capable model** (e.g. `claude-3-5-sonnet`) for image inputs.

## Multi-turn via messages array

For conversational generation, pass an array of role/content messages as the prompt (this is how chat is done in AISQL — there is no separate `CHAT` function to memorize as current):

```sql
SELECT AI_COMPLETE(
    model => 'llama3.1-70b',
    prompt => [
        {'role':'system','content':'You are a concise SQL tutor.'},
        {'role':'user','content':'What is a CTE?'},
        {'role':'assistant','content':'A named temporary result set...'},
        {'role':'user','content':'Show a short example.'}
    ]
);
```

The model is stateless — **you** maintain history by resending the growing `messages` array. Chat-app patterns are covered in [2.5](./2.5_Chat_Interfaces_and_Pipelines.md).

## Cost & monitoring

AISQL bills on **tokens → credits** (input tokens for all functions; output tokens additionally for generative ones like `AI_COMPLETE`). Monitor with account usage:

```sql
SELECT DATE_TRUNC('day', start_time) AS d, model_name, function_name,
       SUM(token_credits) AS credits, SUM(tokens) AS tokens
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_FUNCTIONS_USAGE_HISTORY
WHERE start_time >= DATEADD('day', -30, CURRENT_DATE())
GROUP BY 1,2,3 ORDER BY credits DESC;
```

Cost levers: pick the smallest adequate model, cap `max_tokens`, cache repeated prompts, batch where sensible, and pre-check length with `AI_COUNT_TOKENS`. For steady high-volume/low-latency needs, reserve **Provisioned Throughput** (see [2.4](./2.4_Data_Analysis_By_Use_Case.md)).

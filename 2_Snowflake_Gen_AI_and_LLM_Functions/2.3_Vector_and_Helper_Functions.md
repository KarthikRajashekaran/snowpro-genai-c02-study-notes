# 2.3 Vector & Helper Functions

This page covers the two remaining function groups under objective 2.1: the **VECTOR_\*** functions (distance/similarity, vector math, and vector aggregates) and the **helper functions** (`AI_COUNT_TOKENS`, `TRY_COMPLETE`, `SPLIT_TEXT_RECURSIVE_CHARACTER`, `SPLIT_TEXT_MARKDOWN_HEADER`, `TO_FILE`, `PROMPT`).

## The VECTOR data type

Embeddings are stored in a typed column: `VECTOR(FLOAT, n)` (or `VECTOR(INT, n)`), where `n` is the dimension. `AI_EMBED` returns a `VECTOR(FLOAT, n)`; the vector functions below operate on these values.

```sql
CREATE OR REPLACE TABLE doc_vectors (
    id      INT,
    chunk   STRING,
    embedding VECTOR(FLOAT, 1024)     -- must match the embedding model's dimension
);
```

---

## Distance & similarity functions

These take **two vectors of the same dimension** and return a scalar. They power k-NN / semantic search.

| Function | Returns | Meaning | Best when |
|----------|---------|---------|-----------|
| `VECTOR_COSINE_SIMILARITY(a,b)` | -1 … 1 (higher = closer) | Cosine of the angle; ignores magnitude | **Default for text embeddings**; the go-to for semantic search |
| `VECTOR_INNER_PRODUCT(a,b)` | unbounded (higher = closer) | Dot product; sensitive to magnitude | Max-inner-product search; equivalent to cosine when vectors are **normalized** |
| `VECTOR_L2_DISTANCE(a,b)` | ≥ 0 (lower = closer) | Euclidean straight-line distance | When magnitude matters; clustering |
| `VECTOR_L1_DISTANCE(a,b)` | ≥ 0 (lower = closer) | Manhattan (sum of absolute diffs) | Robust to outliers; sparse/high-dim features |

**Similarity vs distance:** cosine similarity and inner product are **larger when closer** (rank `DESC`); L1/L2 are **distances** — **smaller when closer** (rank `ASC`).

```sql
-- Semantic search: top 5 chunks nearest a query embedding
WITH q AS (
    SELECT AI_EMBED('snowflake-arctic-embed-l-v2.0', 'How do I reset my password?') AS qv
)
SELECT d.id, d.chunk,
       VECTOR_COSINE_SIMILARITY(d.embedding, q.qv) AS sim
FROM doc_vectors d, q
ORDER BY sim DESC          -- similarity: highest first
LIMIT 5;

-- Same search expressed as L2 distance
SELECT d.id, VECTOR_L2_DISTANCE(d.embedding, q.qv) AS dist
FROM doc_vectors d, q
ORDER BY dist ASC          -- distance: lowest first
LIMIT 5;
```

> **Exam tip:** if embeddings are already normalized (unit length), cosine similarity and inner product produce the **same ranking**. Snowflake's own embedding models are normalized, so `VECTOR_COSINE_SIMILARITY` is the safe default.

## Vector math functions

### VECTOR_NORMALIZE(vector [, norm])
**Purpose:** Scale a vector to unit length (L2 norm by default). After normalizing, cosine similarity equals inner product — handy for consistency or when an index expects unit vectors.

```sql
SELECT VECTOR_NORMALIZE(embedding) AS unit_vec FROM doc_vectors;
```

### VECTOR_TRUNCATE(vector, dimension)
**Purpose:** Shorten a vector to its first `dimension` components (Matryoshka-style dimensionality reduction) — trade a little accuracy for smaller storage / faster search when the embedding model supports truncation.

```sql
-- Keep only the first 256 dimensions of a 1024-dim embedding
SELECT VECTOR_TRUNCATE(embedding, 256) AS small_vec FROM doc_vectors;
```

## Vector aggregate functions

These reduce a **column of vectors** (one per row) into a single vector, elementwise, across a group. Useful for building centroids, envelopes and pooled representations.

| Function | Result (elementwise across rows) |
|----------|----------------------------------|
| `VECTOR_SUM(v)` | Sum of vectors |
| `VECTOR_AVG(v)` | Mean vector — a **centroid** (e.g. average embedding of a cluster/topic) |
| `VECTOR_MIN(v)` | Elementwise minimum |
| `VECTOR_MAX(v)` | Elementwise maximum |

```sql
-- Centroid embedding per topic (a "topic vector" you can search against)
SELECT topic, VECTOR_AVG(embedding) AS topic_centroid
FROM doc_vectors
GROUP BY topic;
```

## Helper functions

### AI_COUNT_TOKENS()
**Purpose:** Count tokens for a given model/function before you call it — for cost estimation and to stay under context limits. Replaces `COUNT_TOKENS`.

```sql
SELECT prompt_id,
       AI_COUNT_TOKENS('llama3.1-70b', prompt_text) AS tokens
FROM prompts
WHERE AI_COUNT_TOKENS('llama3.1-70b', prompt_text) < 4000;   -- pre-flight guard
```
**Key parameters:** `model` (or function name), `text`.

### TRY_COMPLETE()
**Purpose:** Error-safe `AI_COMPLETE` — returns NULL instead of raising, so a single bad row won't fail a batch. (Full treatment in [2.2](./2.2_Cortex_LLM_Complete_Functions.md).)

```sql
SELECT id, COALESCE(TRY_COMPLETE('llama3.1-8b', body), 'failed') AS out FROM docs;
```

### SPLIT_TEXT_RECURSIVE_CHARACTER()
**Purpose:** Chunk long text into overlapping pieces for embedding/RAG. It splits **recursively** on a hierarchy of separators (paragraphs → lines → words) to keep chunks near a target size without cutting mid-word. This is the standard chunker feeding `AI_EMBED` / Cortex Search.

```sql
SELECT c.value::string AS chunk
FROM documents d,
     LATERAL FLATTEN(
        SNOWFLAKE.CORTEX.SPLIT_TEXT_RECURSIVE_CHARACTER(
            d.body,
            'markdown',   -- format: 'none' | 'markdown'
            512,          -- chunk_size (characters)
            64            -- overlap (characters shared between adjacent chunks)
        )
     ) c;
```
**Key parameters:** `text`, `format`, `chunk_size`, `overlap`. Returns an ARRAY of chunks.

### SPLIT_TEXT_MARKDOWN_HEADER()
**Purpose:** Chunk **markdown** by its header structure, so each chunk is a coherent section and carries its heading context. Pairs perfectly with `AI_PARSE_DOCUMENT(..., {'mode':'LAYOUT'})` output, which is markdown with headings.

```sql
SELECT c.value AS section
FROM parsed_docs d,
     LATERAL FLATTEN(
        SNOWFLAKE.CORTEX.SPLIT_TEXT_MARKDOWN_HEADER(
            d.markdown,
            {'#':'h1','##':'h2','###':'h3'},   -- headers → metadata keys to split on
            1500                                -- max chunk_size
        )
     ) c;
```
**Key parameters:** `markdown_text`, `headers_to_split_on` (object mapping header markers → labels), `chunk_size`. Returns chunks tagged with their header path.

### TO_FILE()
**Purpose:** Construct a **FILE** value referencing staged content (document, image, audio) so it can be passed to `AI_PARSE_DOCUMENT`, `AI_TRANSCRIBE`, `AI_EXTRACT`, or multimodal `AI_COMPLETE`.

```sql
SELECT AI_TRANSCRIBE(TO_FILE('@calls', 'call_001.mp3'));
SELECT AI_PARSE_DOCUMENT(TO_FILE('@docs', 'contract.pdf'), {'mode':'LAYOUT'});
```
**Key parameters:** `TO_FILE('@stage', 'relative/path')` or `TO_FILE(file_url)`.

### PROMPT()
**Purpose:** Build a prompt object from a **template with positional placeholders** (`{0}`, `{1}`, …), substituting columns and/or `TO_FILE()` references. It's how you mix text and files into one prompt for multimodal `AI_COMPLETE` and how you templatize `AI_FILTER` conditions.

```sql
-- Multimodal: text + image
SELECT AI_COMPLETE('claude-3-5-sonnet',
    PROMPT('Caption this photo for accessibility: {0}',
           TO_FILE('@images','photo.jpg')));

-- Templated AI_FILTER over two columns
SELECT * FROM tickets
WHERE AI_FILTER(PROMPT('Is ticket {0} a duplicate of known issue {1}?', body, known_issue));
```
**Key parameters:** a format string with `{n}` placeholders, followed by the values (columns, literals, or files) to substitute.

1. **Embeddings from Snowflake's models are normalized. Which two functions give the same ranking?**
   - A) L1 and L2  B) Cosine similarity and inner product  C) `VECTOR_SUM` and `VECTOR_AVG`  D) Cosine and L2
2. **When ordering results by `VECTOR_L2_DISTANCE`, the most similar rows are:**
   - A) The largest values (`ORDER BY … DESC`)  B) The smallest values (`ORDER BY … ASC`)  C) Values near 1  D) Negative values
3. **You have markdown produced by `AI_PARSE_DOCUMENT` LAYOUT mode and want section-aware chunks. Use:**
   - A) `SPLIT_TEXT_RECURSIVE_CHARACTER`  B) `SPLIT_TEXT_MARKDOWN_HEADER`  C) `VECTOR_TRUNCATE`  D) `AI_COUNT_TOKENS`
4. **To pass a staged audio file to `AI_TRANSCRIBE`, wrap the path with:**
   - A) `PROMPT`  B) `PARSE_JSON`  C) `TO_FILE`  D) `VECTOR_NORMALIZE`
5. **Which function produces a centroid (mean) embedding per group?**
   - A) `VECTOR_MAX`  B) `VECTOR_SUM`  C) `VECTOR_AVG`  D) `VECTOR_INNER_PRODUCT`
6. **Which helper both estimates cost and prevents exceeding a model's context window?**
   - A) `TRY_COMPLETE`  B) `AI_COUNT_TOKENS`  C) `TO_FILE`  D) `VECTOR_TRUNCATE`

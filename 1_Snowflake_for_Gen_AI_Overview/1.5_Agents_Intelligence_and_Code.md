# 1.5 Agents, Intelligence & Code

This section covers Snowflake's agentic and developer-facing Gen AI layers: **Cortex Agents**, **Snowflake Intelligence**, **Cortex Code** (Snowsight UI + CLI), **Snowflake Copilot**, **cross-region inference**, and **Cortex Knowledge Extensions**.

---

## Cortex Agents

### What they are
**Cortex Agents** are an orchestration layer that lets an LLM **plan and use tools** to answer complex, multi-step requests over your Snowflake data. Rather than a single function call, an agent **reasons about the question, selects tools, calls them (possibly several times), and composes a final grounded answer** — often with citations.

### Orchestration over Search + Analyst + tools
An agent combines Snowflake's building blocks as **tools**:
- **Cortex Analyst** — for structured, numeric, text-to-SQL questions.
- **Cortex Search** — for unstructured retrieval / RAG.
- **Custom tools** — stored procedures, user-defined functions, or external tools the agent may call.

The agent's planner decides *which* tool to use *when*. For example: "Summarize Q3 churn and the top complaint themes" → call **Analyst** for the churn numbers and **Search** for the complaint documents, then synthesize both.

### How it's used
- Exposed via a **REST API** (and consumable by external clients, including through **MCP**).
- Configured with instructions, a model, and a set of tool resources (which search services / semantic models it may use).
- The foundation under **Snowflake Intelligence**.

---

## Snowflake Intelligence

**Snowflake Intelligence** is the **natural-language agent experience** — a ready-made app (in Snowsight) where business users chat with their data. It is built **on top of Cortex Agents** and stitches together **Cortex Analyst** (structured) and **Cortex Search** (unstructured) so users can ask questions spanning both, get answers with sources, and take follow-up actions — without writing SQL or building an app themselves.

**Agents vs Intelligence (exam framing):**
- *Cortex Agents* = the **orchestration API / building block**.
- *Snowflake Intelligence* = the **end-user application experience** built on agents.

## Snowflake Cortex Code

**Cortex Code** is Snowflake's AI coding assistant for developers working with Snowflake. It helps write and understand SQL and Python, explains objects and errors, and speeds up data engineering and Gen AI development. It comes in two form factors:

### Cortex Code in the Snowsight UI
An **in-Snowsight assistant** that helps you author and debug code directly in worksheets/notebooks — generate SQL from intent, explain a query, fix errors, and answer questions about your account's objects, all within the governed Snowsight environment.

### Cortex Code CLI
A **command-line interface** that brings the same AI coding assistance to the terminal and local developer workflow.

**Key features:**
- Natural-language chat to generate/refactor/explain SQL and Python
- Awareness of Snowflake context (objects, schemas) for grounded help
- **Session management** — conversations run in sessions so context/history carry across turns; you can start a new session, continue an existing one, and clear/reset context
- Fits into scripts and local dev loops outside Snowsight

**Representative commands (verify exact flags in current docs):**
```bash
# Start an interactive assistant session
cortex code

# Ask a one-off question non-interactively
cortex code "write a query for top 10 customers by revenue this year"

# Session management: continue a prior session / start fresh
cortex code --continue          # resume the most recent session
cortex code --new               # start a new session (fresh context)
```
> Command names/flags for the CLI evolve — treat the above as the *shape* of the interface (interactive session, one-off prompt, session continue/new), and confirm specifics in the current Snowflake documentation.

## Snowflake Copilot Inline [Public Preview]

**Snowflake Copilot** is an LLM-powered assistant embedded in Snowsight. **Copilot Inline** (Public Preview) brings suggestions **directly inline in the SQL editor** — as you type, it can suggest completions and generate SQL from natural-language comments in place, rather than only in a side panel. It draws on **Cortex Models & Functions**, can leverage **Cortex Search** over documentation/context for RAG-grounded help, and benefits from **Cortex Fine-tuning** where applicable. It is schema-aware and governed by Snowflake RBAC.

## Cross-Region Inference

Some models are not available in every Snowflake region. **Cross-region inference** lets a request be **processed by a model hosted in another region** when it isn't available locally, so you can use a model without migrating your data's region.

### The `CORTEX_ENABLED_CROSS_REGION` account parameter
Cross-region inference is **disabled by default**. An account administrator enables it and scopes *where* requests may travel:
```sql
-- Disabled (default): requests never leave the local region
ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'DISABLED';

-- Allow inference in any region where the model is available
ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';

-- Restrict to a specific cloud/region grouping (e.g., AWS US regions)
ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'AWS_US';
```
> Accepted values (e.g., `DISABLED`, `ANY_REGION`, and cloud/region groupings such as `AWS_US`) and their exact spellings are defined in the current docs — confirm before use.

### Considerations
- **Availability** — the main reason to enable it: reach models not offered in your home region, and improve resilience.
- **Latency** — routing a request to another region adds network round-trip time.
- **Data movement / governance** — the **prompt/inference payload is processed in the remote region**; ensure this is acceptable for your compliance, data-residency, and privacy requirements before enabling. (Snowflake does not train on this data, but it does leave the home region during inference.)
- **Only the request is cross-region** — your stored data stays where it is; only the inference call travels.

## Cortex Knowledge Extensions (CKE)

**Cortex Knowledge Extensions** are **packaged, third-party knowledge sources** distributed through the **Snowflake Marketplace** that you can plug into your Gen AI apps. A provider (e.g., a publisher or content vendor) shares curated, searchable content as a CKE; a consumer can then use it as a knowledge source for **RAG / Cortex Search** and **agents** — grounding answers on licensed, up-to-date external content **without building or maintaining that corpus themselves**, and with the provider's IP kept protected. In short: CKEs let you extend an agent's knowledge with trusted external content via the Marketplace.

# 3.2 RBAC Roles & Privileges

This section covers **granting and revoking RBAC and privileges** for Cortex services — objective 3.2. Cortex access is delivered through **database roles that live in the shared `SNOWFLAKE` database**. You grant these database roles to your own account roles, and every Cortex service checks for the specific role(s) it requires.

## The Cortex Database Roles

Database roles are named `SNOWFLAKE.<ROLE>` and are granted to account roles. The four you must know for C02:

| Database role | Grants access to | Notes |
|---------------|------------------|-------|
| `SNOWFLAKE.CORTEX_USER` | Cortex **LLM/AI functions** (`COMPLETE`, `AI_COMPLETE`, `SUMMARIZE`, `SENTIMENT`, `TRANSLATE`, etc.) | Granted to **`PUBLIC`** by default; revoke to lock down. |
| `SNOWFLAKE.CORTEX_ANALYST_USER` | **Cortex Analyst** (text-to-SQL over semantic models) | Required to call the Analyst API/endpoint. |
| `SNOWFLAKE.CORTEX_AGENT_USER` | **Cortex Agents** (orchestration over Analyst + Search + tools) | Required for agent runs and Snowflake Intelligence. |
| `SNOWFLAKE.CORTEX_EMBED_USER` | **Embedding** functions (`EMBED_TEXT_768`, `EMBED_TEXT_1024`) | Scopes who can generate embeddings. |

### Granting Cortex Database Roles

```sql
-- Base LLM/AI functions
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER TO ROLE gen_ai_developer;

-- Cortex Analyst
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_ANALYST_USER TO ROLE analyst_rw;

-- Cortex Agents / Snowflake Intelligence
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_AGENT_USER TO ROLE agent_operator;

-- Embeddings
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_EMBED_USER TO ROLE rag_pipeline;
```

### Revoking Cortex Database Roles

Because `SNOWFLAKE.CORTEX_USER` is granted to `PUBLIC` by default, a common governance step is to **revoke it from `PUBLIC`** and re-grant it only to approved roles:

```sql
-- Lock down: remove the default broad grant, then grant selectively
REVOKE DATABASE ROLE SNOWFLAKE.CORTEX_USER FROM ROLE PUBLIC;
GRANT  DATABASE ROLE SNOWFLAKE.CORTEX_USER TO   ROLE gen_ai_developer;

-- Remove a specific team's access to Agents
REVOKE DATABASE ROLE SNOWFLAKE.CORTEX_AGENT_USER FROM ROLE agent_operator;
```

## Per-Service Privilege Requirements

Each Cortex service needs its database role **plus** ordinary object privileges on the data/objects it touches. Know these combinations:

### Cortex Analyst
- `SNOWFLAKE.CORTEX_ANALYST_USER` database role
- `USAGE` on the **database and schema** holding the **semantic model / semantic view**
- `SELECT` on the tables/views the semantic model references
- If the semantic model YAML lives on a **stage**: `READ` on that stage

```sql
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_ANALYST_USER TO ROLE analyst_rw;
GRANT USAGE ON DATABASE sales_db TO ROLE analyst_rw;
GRANT USAGE ON SCHEMA sales_db.semantics TO ROLE analyst_rw;
GRANT SELECT ON ALL TABLES IN SCHEMA sales_db.curated TO ROLE analyst_rw;
```

### Cortex Search
- Access to the **Cortex Search Service** object: `USAGE` on its database/schema and the search service
- `SNOWFLAKE.CORTEX_USER` is required because indexing/serving uses embedding + LLM functions
- A **virtual warehouse** with `USAGE` for building/refreshing the index

```sql
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER TO ROLE search_consumer;
GRANT USAGE ON CORTEX SEARCH SERVICE kb_db.kb.docs_search TO ROLE search_consumer;
GRANT USAGE ON WAREHOUSE search_wh TO ROLE search_consumer;
```

### Cortex Agents
- `SNOWFLAKE.CORTEX_AGENT_USER` database role
- The **downstream** privileges for each tool the agent uses — typically `CORTEX_ANALYST_USER` (Analyst tool) and `USAGE` on any Cortex Search service it calls
- `USAGE` on the database/schema containing the **agent object**

### Snowflake Intelligence
- Built on Cortex Agents, so it requires `SNOWFLAKE.CORTEX_AGENT_USER`
- Plus the underlying Analyst/Search privileges for the agents it exposes

> **Exam tip:** An agent inherits nothing automatically — the **calling role** must independently hold every privilege the agent's tools need (Analyst role, Search service usage, warehouse usage). "Agent works for me but not my teammate" is almost always a missing downstream grant.

## Application Roles: Grant, Revoke, and Limit Access

Managed features and Native Apps expose **application roles**. Granting or revoking them adds or removes the feature for an account role, and is how you **limit a capability to specific roles**.

```sql
-- Grant an application role to expose the capability
GRANT APPLICATION ROLE intelligence_app.app_user TO ROLE business_analyst;

-- Revoke a privilege previously granted on/through an application role
REVOKE APPLICATION ROLE intelligence_app.app_user FROM ROLE business_analyst;
```

To **limit access to specific roles**, revoke broad/default grants (like the `PUBLIC` grant of `CORTEX_USER`) and re-grant only to the named roles that need them. Follow least privilege: grant the narrowest role to the narrowest set of consumers.

## Verifying Grants

```sql
-- What database roles does a role hold?
SHOW GRANTS TO ROLE gen_ai_developer;

-- Who holds a given database role?
SHOW GRANTS OF DATABASE ROLE SNOWFLAKE.CORTEX_USER;

-- Effective privileges for the current session
SELECT * FROM TABLE(INFORMATION_SCHEMA.GRANTED_TO_ROLE());
```

## Study Questions

1. **Which database role is required to call `SNOWFLAKE.CORTEX.COMPLETE`?**
   - A) `SNOWFLAKE.CORTEX_AGENT_USER`
   - B) `SNOWFLAKE.CORTEX_USER`
   - C) `SNOWFLAKE.CORTEX_ANALYST_USER`
   - D) `ACCOUNTADMIN`

2. **By default, `SNOWFLAKE.CORTEX_USER` is granted to:**
   - A) `ACCOUNTADMIN` only
   - B) `SYSADMIN` only
   - C) `PUBLIC`
   - D) No one

3. **A user can run an agent but their teammate cannot. The MOST likely cause is:**
   - A) The teammate is missing a downstream grant (e.g., `CORTEX_ANALYST_USER` or Search service `USAGE`)
   - B) The allowlist is set to `All`
   - C) Cross-region inference is enabled
   - D) The warehouse is too small

4. **Which role gates generating embeddings with `EMBED_TEXT_1024`?**
   - A) `CORTEX_EMBED_USER`
   - B) `CORTEX_AGENT_USER`
   - C) `CORTEX_ANALYST_USER`
   - D) `CORTEX_SEARCH_USER`

5. **How do you restrict Cortex functions to only approved roles?**
   - A) Drop the `SNOWFLAKE` database
   - B) `REVOKE DATABASE ROLE SNOWFLAKE.CORTEX_USER FROM ROLE PUBLIC`, then grant selectively
   - C) Set `CORTEX_MODELS_ALLOWLIST = 'None'`
   - D) Disable cross-region inference

**Answers: 1-B, 2-C, 3-A, 4-A, 5-B**

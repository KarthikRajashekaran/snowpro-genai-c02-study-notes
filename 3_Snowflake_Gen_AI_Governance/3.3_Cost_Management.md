# 3.3 Cost Management

This section covers how to **manage, monitor, and optimize Cortex costs** — objective 3.3. Cortex AI services are billed in **Snowflake credits**, driven mostly by **token consumption** (AI functions, Agents, Analyst) and **warehouse/serving compute** (Search, Container Services). You monitor spend through **ACCOUNT_USAGE views**, control it with **usage quotas**, and attribute it with **object tagging**.

## Cost Drivers Per Service

| Service | Primary cost driver | How to optimize |
|---------|---------------------|-----------------|
| **Cortex AI functions** (`COMPLETE`, `AI_COMPLETE`, `SUMMARIZE`, etc.) | **Tokens processed** (input + output), scaled by model size | Minimize tokens: trim prompts, choose smaller models, batch, cache |
| **Cortex Analyst** | Per-message/token usage for text-to-SQL generation | Fewer, well-formed questions; verified queries reduce retries |
| **Cortex Search** | **Indexing** (embedding generation via `EMBED_TEXT`) + **serving** (query-time compute) + a **virtual warehouse** for index build/refresh | Right-size the warehouse; control refresh frequency; limit indexed columns |
| **Cortex Agents** | Sum of all tool calls — **token usage** across Analyst + Search + LLM reasoning steps | **Limit token usage**; cap tool iterations; scope tools tightly |
| **Snowpark Container Services** | **Compute pools** (node type × uptime) | Track compute-pool usage; suspend idle pools |

> **Exam tip:** LLM/AI-function pricing is **token-based** — the biggest lever is reducing tokens (shorter prompts, smaller models, fewer calls). Cortex Search adds **warehouse** cost for indexing on top of token cost for embeddings.

## Tracking Usage: ACCOUNT_USAGE & Metadata Views

Consumption is exposed in `SNOWFLAKE.ACCOUNT_USAGE`. Know each view and what it measures:

| View | What it tracks |
|------|----------------|
| `METERING_DAILY_HISTORY` | **Daily credit usage by service type** — the go-to for AI credits |
| `METERING_HISTORY` | **Hourly** credit usage by service |
| `CORTEX_FUNCTIONS_USAGE_HISTORY` | Token & credit usage for Cortex **LLM/AI functions** |
| `CORTEX_AISQL_USAGE_HISTORY` | Usage for **AISQL** (AI_* SQL functions) |
| `CORTEX_ANALYST_USAGE_HISTORY` | **Cortex Analyst** message/usage history |
| `CORTEX_SEARCH_DAILY_USAGE_HISTORY` | **Cortex Search** daily serving/indexing usage |
| `CORTEX_REST_API_USAGE_HISTORY` | Usage driven through the **Cortex REST API** |
| `CORTEX_PROVISIONED_THROUGHPUT_USAGE_HISTORY` | **Provisioned throughput** capacity usage |

### The Official Sample-Question Fact

To find **daily credit usage for AI services**, query `METERING_DAILY_HISTORY` and filter `SERVICE_TYPE = 'AI_SERVICES'`:

```sql
-- Daily AI-service credit consumption (the exam's expected answer)
SELECT
    usage_date,
    service_type,
    credits_used
FROM SNOWFLAKE.ACCOUNT_USAGE.METERING_DAILY_HISTORY
WHERE service_type = 'AI_SERVICES'
ORDER BY usage_date DESC;
```

### Per-Service Monitoring Queries

```sql
-- Token & credit usage for Cortex AI functions, by model
SELECT
    function_name,
    model_name,
    SUM(token_credits)  AS credits,
    SUM(tokens)         AS total_tokens
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_FUNCTIONS_USAGE_HISTORY
GROUP BY function_name, model_name
ORDER BY credits DESC;

-- Cortex Analyst usage over the last 30 days
SELECT *
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_ANALYST_USAGE_HISTORY
WHERE start_time >= DATEADD('day', -30, CURRENT_TIMESTAMP());

-- Cortex Search daily usage
SELECT *
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_SEARCH_DAILY_USAGE_HISTORY
ORDER BY usage_date DESC;
```

> **Latency note:** `ACCOUNT_USAGE` views can lag up to ~45 minutes to a few hours. For near-real-time checks use `INFORMATION_SCHEMA` table functions where available.

## Controlling Spend: Usage Quotas & Resource Monitors

Cap Cortex/AI credit consumption with **usage quotas** and **resource monitors** on the warehouses that drive AI compute:

```sql
-- Resource monitor to cap monthly credits on the AI warehouse
CREATE OR REPLACE RESOURCE MONITOR ai_services_monitor
    WITH CREDIT_QUOTA = 500
    FREQUENCY = MONTHLY
    START_TIMESTAMP = CURRENT_TIMESTAMP()
    TRIGGERS
        ON 75  PERCENT DO NOTIFY
        ON 90  PERCENT DO SUSPEND
        ON 100 PERCENT DO SUSPEND_IMMEDIATE;

ALTER WAREHOUSE search_wh SET RESOURCE_MONITOR = ai_services_monitor;
```

For Agents specifically, **limit token usage** by capping the number of tool-calling iterations and scoping the tools the agent may invoke, so a single request cannot run away with tokens.

## Attributing Cost With Object Tagging

**Object tags** let you attribute AI-service credits to a cost center, team, or project. Create a tag, apply it to the warehouses/objects that run AI workloads, then join usage back to tags.

```sql
-- 1. Create a cost-attribution tag
CREATE TAG IF NOT EXISTS governance.tags.cost_center
    ALLOWED_VALUES 'gen_ai', 'analytics', 'platform';

-- 2. Apply it to the warehouse serving AI workloads
ALTER WAREHOUSE search_wh SET TAG governance.tags.cost_center = 'gen_ai';

-- 3. Report credits by tag value
SELECT
    tr.tag_value       AS cost_center,
    SUM(mh.credits_used) AS credits
FROM SNOWFLAKE.ACCOUNT_USAGE.METERING_HISTORY mh
JOIN SNOWFLAKE.ACCOUNT_USAGE.TAG_REFERENCES tr
    ON mh.name = tr.object_name
   AND tr.tag_name = 'COST_CENTER'
GROUP BY tr.tag_value
ORDER BY credits DESC;
```

> **Exam tip:** **Object tagging** is the sanctioned way to monitor and attribute AI-service costs across teams — pair tags with `METERING_*` views to build chargeback reports.

## Cost-Optimization Checklist

- ✅ Minimize tokens: shorter prompts, smaller models, batch calls, reuse cached results
- ✅ Right-size and auto-suspend warehouses used for Cortex Search indexing
- ✅ Limit Agent tool iterations to cap token blow-ups
- ✅ Suspend idle Snowpark Container Services compute pools
- ✅ Apply resource monitors / usage quotas to AI warehouses
- ✅ Tag AI objects and report spend from `METERING_DAILY_HISTORY`

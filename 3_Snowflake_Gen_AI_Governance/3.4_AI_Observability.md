# 3.4 AI Observability

This section covers **Snowflake AI Observability** — objective 3.4. Observability lets you **evaluate, compare, trace, and log** the behavior of generative-AI apps (RAG pipelines, Cortex Analyst, Agents) so you can measure quality, catch regressions, and debug failures. In Snowflake it is built on the **TruLens** framework, and evaluation/trace data lands in **event tables**.

## What AI Observability Provides

| Capability | What it does |
|------------|--------------|
| **Evaluation metrics** | Score app output for quality (relevance, groundedness, correctness) using LLM-as-a-Judge |
| **Comparisons** | Compare runs/versions side by side (e.g., prompt A vs prompt B, model X vs model Y) |
| **Tracing** | Capture the full execution path — retrieval, prompt, model call, tool calls — as spans |
| **Logging** | Persist inputs, outputs, and intermediate steps for audit and debugging |
| **Event tables** | The storage backing traces and evaluation results |

## Event Tables: The Storage Layer

Traces, logs, and evaluation records are written to an **event table**. You configure an event table at the account or database level so telemetry from AI apps is captured.

```sql
-- Create and register an event table to capture traces/logs
CREATE EVENT TABLE IF NOT EXISTS observability_db.telemetry.ai_events;

ALTER ACCOUNT SET EVENT_TABLE = observability_db.telemetry.ai_events;

-- Query captured traces
SELECT record_type, timestamp, resource_attributes, record
FROM observability_db.telemetry.ai_events
ORDER BY timestamp DESC;
```

## Instrumentation With the TruLens SDK

Snowflake AI Observability uses the **TruLens SDK** (available via the `trulens` / `snowflake-ml-python` Python packages) to instrument an application, run evaluations, and record results back into Snowflake. The typical flow:

1. **Register the app** you want to observe (a "TruApp" wrapping your RAG/agent function).
2. **Define feedback functions** (the metrics) — often LLM-as-a-Judge evaluators.
3. **Run** the app over a test set; TruLens captures traces and computes metrics.
4. **Review** results and comparisons in Snowsight or by querying the event table.

```python
# Conceptual TruLens instrumentation (run in a Snowflake Notebook / Python worksheet)
from trulens.core import TruSession
from trulens.apps.custom import TruApp
from trulens.core import Feedback

session = TruSession()  # connected to Snowflake; results persist to the event table

# Wrap the RAG/agent app so calls are traced
tru_app = TruApp(
    my_rag_app,
    app_name="support_rag",
    app_version="v1",
    feedbacks=[context_relevance, groundedness, answer_relevance],
)

# Run the app over an evaluation dataset; traces + metrics are logged
with tru_app as recording:
    for question in eval_questions:
        my_rag_app.answer(question)
```

## Evaluating AI Applications: LLM-as-a-Judge & the RAG Triad

Evaluation uses **LLM-as-a-Judge**: a model scores each response against a rubric. For RAG apps, the canonical metric set is the **RAG Triad**:

| RAG Triad metric | Question it answers | Detects |
|------------------|---------------------|---------|
| **Context Relevance** | Is the *retrieved context* relevant to the question? | Poor retrieval / bad search |
| **Groundedness** | Is the *answer supported by* the retrieved context? | Hallucination (answer not backed by sources) |
| **Answer Relevance** | Does the *answer* actually address the question? | Off-topic or evasive answers |

Together the triad localizes failures: low **context relevance** points at the retriever; low **groundedness** points at the generator hallucinating; low **answer relevance** points at prompt/response quality. Beyond the triad, you can add metrics such as **correctness**, **coherence**, and **harmfulness/safety**.

```sql
-- Example: inspect evaluation scores logged by TruLens in the event table
SELECT
    record:app_name::string        AS app,
    record:app_version::string     AS version,
    record:metric_name::string     AS metric,
    AVG(record:score::float)       AS avg_score
FROM observability_db.telemetry.ai_events
WHERE record_type = 'EVALUATION'
GROUP BY 1, 2, 3
ORDER BY app, version, metric;
```

## Comparisons and Tracing in Practice

- **Comparisons:** Run two `app_version`s (e.g., different prompts, models, or chunk sizes) over the same evaluation set, then compare average RAG-Triad scores to decide which to ship.
- **Tracing:** Each run produces spans for retrieval, prompt assembly, and generation. Tracing shows *where* latency or errors occur and *what context* was retrieved — essential for debugging low groundedness.
- **Logging:** Persisted inputs/outputs give an audit trail for governance and let you replay failures.

> **Exam tip:** Snowflake AI Observability = **TruLens SDK + event tables**. The **RAG Triad** is **context relevance, groundedness, answer relevance**, and it is scored with **LLM-as-a-Judge**. Groundedness is the metric that specifically detects **hallucination**.
